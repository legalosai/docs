<Update label="August 19, 2026" description="Week of August 17">

## Bug fixes

- **Onboarding wizard no longer fails silently.** Completing onboarding could return you to the start with no toast, no inline error, and no console output when a hidden field was invalid. Blocked submits and blocked **Next** clicks now always surface the offending field with an inline error, and the wizard jumps to the step that owns it.
- **Scraped company phone numbers now import cleanly.** When LegalOS scraped a company website during onboarding, the raw phone string was written into a field that only accepted E.164 and was then rejected without explanation. Extraction now pulls the first valid number out of the scraped text and normalizes it before saving.
- **Website scrape no longer overwrites fields you've already edited.** Onboarding pre-fill from a website scrape is fill-only. If you've typed or corrected a value, a later scrape leaves it alone.
- **Company step accepts zero US employees.** Petitioners with no US-based staff can now submit the company step, which previously rejected `0` as invalid.

</Update>

<Update label="August 18, 2026" description="Week of August 17">

## New features

**Form I-129S for blanket L-1 petitions.** LegalOS now generates the I-129S (Nonimmigrant Worker Based on a Blanket L Petition) end-to-end for L-1A and L-1B cases filed under an approved blanket L petition.

- New intake fields capture the blanket petition details and any offsite third-party worksite supervision required by USCIS.
- I-129S is offered as a conditional add-on on L-1A and L-1B petitions, not a default required form, so standard individual L filings are unchanged.
- The generated form places the beneficiary's signature on Page 6, Part 7, #6, verified against the current USCIS PDF.

**ChatGPT connector support for LegalOS MCP.** The LegalOS MCP server now supports ChatGPT alongside Claude, so ChatGPT users can connect to LegalOS without an operator provisioning step.

- Zero-approval install for the ChatGPT connector: registration is auto-provisioned against the trusted `https://chatgpt.com/connector/oauth/` redirect prefix.
- Trust is scoped to a single redirect URI per registration, not a family of URIs, so other clients aren't inadvertently trusted.
- Per-operation gates, consent prompts, rate limits, and row-level security are unchanged from the existing Claude integration.

</Update>

<Update label="August 14, 2026" description="Week of August 10">

## Bug fixes

- **Documents no longer disappear from petitions when a second document is added in the same category.** Linking a document to a company or person previously demoted every other document in the same category (for example, letterhead or pay stubs) to non-current, which hid it from the petition's form data. Linking now leaves siblings alone, so distinct documents in the same category stay visible. Already-hidden documents have been restored automatically — no action needed.

</Update>

<Update label="August 13, 2026" description="Week of August 10">

## New features

**LegalOS MCP server is generally available.** The MCP server for Claude is now open to all customers by default. No allowlist, no per-user approval — connect Claude to LegalOS and start working.

- **Zero-approval install.** Trusted Claude connector clients are provisioned automatically at registration, so end users no longer wait on an operator to enable access.
- **Open-by-default access.** Access is now allow-by-default with block-by-exception, replacing the previous pilot allowlist. Per-operation gates, rate limits, consent prompts, and row-level security are unchanged.
- **Recommenders parity with the app.** MCP recommenders tools now respect the same launch-eligibility rules as the chat and form surfaces, so what Claude can do lines up with what the app can do on the same case.
- **Evidence read/write hardening.** Evidence tools now work cleanly against protected upstream environments, with tighter URL handling on read and write.

## Bug fixes

- **No more spurious `409 revision_mismatch` on intake writes.** Beneficiary intake writes now return the recomputed revision token in the response, so a client's next optimistic write no longer fails with a stale-revision conflict. Previously, updating a field like a phone number and then updating a second field back-to-back could hit a 409 on the second write.

</Update>

<Update label="August 12, 2026" description="Week of August 10">

## New features

**EB-2 NIW petitions on platform.** LegalOS now supports EB-2 National Interest Waiver petitions end-to-end, with parity to the existing EB-1A workflow.

- Both filing routes are supported: **self-petitioned** (filed by the beneficiary) and **employer-sponsored**.
- Evidence is organized into two folders that map to the *Matter of Dhanasar* test: **substantial merit and national importance** (prong 1) and **beneficiary qualifications** (EB-2 threshold plus prong 2).
- Auto-generation of the **I-140** with NIW-specific mapping.
- **ETA-9089 Appendix A** and **ETA-9089 Final Determination** are collected and signed as part of the filing packet, so a common intake-rejection cause is handled up front.

</Update>

<Update label="August 10, 2026" description="Week of August 10">

## New features

**Unified case status across the platform.** Every petition now carries a single, persisted status snapshot that drives the same view for staff and clients.

- A **"ball in court"** badge on each case shows who owes the next action — the client, the attorney, or the signatory — so it's immediately clear where a case is stuck.
- A new **staff work queue** surfaces cases that need attention and hides those that are waiting on client work, so you can triage without hunting through the full list.
- The `Waiting On` column and the badge on the same row now agree, and cases past the signature window no longer claim client work is outstanding.
- Existing petitions are backfilled automatically. Terminal states (withdrawn, archived) are excluded from the queue.

**LegalOS MCP server for Claude.** The production Model Context Protocol server is live, letting Claude read case status, requirements, and intake data on your behalf.

- **Credential-free install** — connect Claude to LegalOS without pasting API keys.
- New tools include `get_case_status` and `list_cases`, backed by the same unified status model as the app.
- Clearer auth-rejection diagnostics tell you exactly why a connection was refused instead of a generic failure.

## Updates

- **`filed` replaces `submitted` in the case-status API.** The public case-status contract renames `submitted` to `filed` and adds a new `in-review` value. Filed cases now read "Filed" everywhere — badge, list, and `GET /api/v1/petitions/{id}/status`. If you consume the case-status API directly, update any code that matches on `submitted`.
- **RFE notice transcription is more reliable.** RFE (Request for Evidence) notice PDFs are now transcribed with OpenAI instead of relying on a text layer being present, so scanned or image-based notices extract cleanly and downstream RFE analysis runs on the full text.
- **Cleaner evidence sidebar.** The "Get Legal Guidance" card has been removed from the evidence sidebar to reduce clutter on the criteria workflow.

## Bug fixes

- **Dead UI controls now work.** Fixed the review deep-link, several attorney-side buttons, and the legacy evidence forms that had stopped responding to clicks. Every control on those surfaces is wired back up.

</Update>

<Update label="August 4, 2026" description="Week of August 3">

## Bug fixes

- **Send-for-signature works again for returning signatories.** Sending employer forms to a company signatory who already had a LegalOS profile was failing with a database error, blocking the signing flow. The signatory-provisioning path now correctly looks up existing memberships and reuses active owners without a redundant write, so send-for-signature completes cleanly and the signatory receives their set-password invite and signing link as expected. Brand-new signatories were never affected.

</Update>

<Update label="August 3, 2026" description="Week of August 3">

## Updates

- **Short case codes for every petition.** Every petition now has a short 5-character case code (drawn from an unambiguous alphabet — no `0`, `O`, `1`, `I`, or `L`) that's shown as the user-facing case identifier and works as a route key alongside the existing UUID. Existing petitions are backfilled automatically, so you can share and reference a case with a code that's easy to read out loud without collisions across the platform.

## Bug fixes

- **Letter comments no longer disappear on save.** Recommendation-letter comment threads are now stored in Postgres as the source of truth, with the `.docx` acting purely as the wire format the editor speaks. A save can never silently erase a comment: resolve and delete are explicit actions, and comments whose anchor paragraph is deleted surface in the workspace side panel as orphaned instead of vanishing.
- **Intake save reliability.** Fixed an issue where beneficiary intake saves could fail to persist under certain conditions.

</Update>

<Update label="July 27, 2026" description="Week of July 27">

## Bug fixes

- **RFE notice uploads now process reliably in production.** Uploading an RFE (Request for Evidence) notice PDF was failing to extract text on production workers, blocking downstream RFE analysis. PDF text extraction now runs cleanly end-to-end so RFE uploads complete and analysis kicks off as expected.
- **Recommendation letter generation runs again.** Background tasks (including recommendation letter drafts) were failing to start in production after a recent dependency update. Task workers now run on a compatible runtime, so recommendation letter generation and other background jobs kick off normally.

</Update>

<Update label="July 24, 2026" description="Week of July 20 – July 24">

## New features

**L-1A petitions on platform.** LegalOS now supports L-1A (intracompany manager or executive) petitions end-to-end alongside the existing visa types.

- Full L-1A intake with a dedicated evidence criteria set seeded automatically when a petition is created.
- Auto-generation of the I-129L Supplement, mapped for L-1A filings.

**Multi-recipient filing sends and mark-as-filed.** File copies and filing documents can now be sent to more than one recipient, and petitions can be explicitly marked as filed once submitted to USCIS.

- Send file copies and receipt notices to multiple recipients on a single petition, tracked per recipient.
- A combined filing email bundles the filing documents into one send instead of sending them piecemeal.
- Mark a petition as filed to capture the filing date and reflect status downstream.

## Updates

- **Deep-linked "Incomplete Sections" in review.** The review step's Incomplete Sections list now links straight to the exact field that needs attention, so you can jump from the checklist to the missing input in one click instead of hunting through the section.

## Bug fixes

- **Account creation no longer misassigns company owners.** A server-side guard prevents new owner accounts from being silently attached to the wrong company when the client picker is skipped or misused — owners with no company selected are now routed to onboarding as intended.

</Update>

<Update label="July 20, 2026" description="Week of July 20">

## New features

**One-click recommendation letter drafts.** Generate a full recommendation letter draft for a recommender in a single click, grounded in their LinkedIn background so the tone and credentials line up with the person signing it.

- Recommender bios are enriched from LinkedIn before drafting so letters reference real accomplishments and titles.
- Business-letter format end-to-end — seeded prompts, agent instructions, and the DOCX export all produce a properly typeset business letter ready to send.
- A pre-generation URL gate confirms the recommender's LinkedIn is captured before a draft kicks off, so you don't burn a generation on missing context.

**Assistant workspace for letter drafting.** The letter-generation surface now has a working area built for iteration.

- Persistent quick actions stay in reach so you can steer a draft without hunting through menus.
- Stop or redraft on demand when a generation is heading the wrong direction.
- Clickable source references open the underlying evidence and deep-link into the exact spot they came from.
- A live draft timer shows generation progress in real time.

## Updates

- **Checkboxes now print on finalized signing copies.** The finalized, client-facing PDF for signing forms (including G-28 and I-129) now preserves every checked box when flattened for wet signature — checked boxes render as an X on the printed copy instead of disappearing. The working copy stays fully interactive and editable.

</Update>

<Update label="July 17, 2026" description="Week of July 13 – July 17">

## New features

**TN (USMCA professional) petitions.** LegalOS now supports TN petitions for Canadian and Mexican professionals under the USMCA, with two filing routes modeled as distinct visa types so you can pick the right path per case.

- **TN at the port of entry** for Canadian nationals — no I-129 required.
- **TN change of status / extension** through USCIS — files the I-129 plus the new Trade Agreement Supplement.
- Split beneficiary and employer intake with a dedicated profession/qualification step.
- Auto-generation of the I-129 Trade Agreement Supplement is wired into signing and signature-location flows alongside the base I-129.

**Online vs. mail USCIS filing fees.** The admin Filing Fee Invoice card now has a toggle for online vs. mail filing, and the seeded fee catalog carries both amounts where USCIS charges different rates. Switching modes re-prices only the catalog lines you haven't edited, so custom line items stay intact.

## Updates

- **Anvil form field auto-fit.** Long names, company names, and addresses now shrink to fit inside single-line fields on generated Anvil forms instead of clipping at the edges. Applies across every visa type.
- **Documents Needed checklist.** The documents-needed checklist now populates from bundle uploads before a section is marked complete, and bundle sections have their own Mark Complete action so progress reflects reality as you go.
- **Graceful version-skew handling on every route.** The update banner and stale-client refresh prompt are now mounted app-wide, so any route can surface a refresh prompt when a new build ships mid-session instead of silently failing a server action. Stale-client errors are also reported to Sentry.

## Bug fixes

- **Stable evidence strength ratings.** Per-bundle reported strength for critical role and original contributions no longer changes between views. Ratings are now cached against the evidence input and only re-evaluated when that input actually changes.
- **Download all evidence.** Fixed a crash in the admin "Download all evidence" action when an entry's source was stored as a provenance object rather than a plain string.

</Update>

<Update label="July 13, 2026" description="Week of July 13">

## New features

**E-3 petitions on platform.** You can now run E-3 (Australian specialty occupation) petitions end-to-end in LegalOS, alongside H-1B and other supported visa types.

- Full E-3 intake for both employer and beneficiary, including a dedicated current immigration status step, specialty occupation details, and processing options.
- Australian-nationality validation on the beneficiary side to catch eligibility issues before submission.
- Auto-generation of the E-3 form set (I-129, LCA, G-28, I-907) with E-3–specific I-129 mapping: classification set to E-3, basis 2.b, requested action 4.c, and Part 3 populated from the beneficiary's current status.
- Filings are routed to the Vermont Service Center (VSC) by default.
- No evidence module is required for E-3, so the workflow skips it automatically.

## Updates

- **Shared address component for H-1B secondary worksites.** The H-1B secondary work-location address now uses the same standardized address input as the rest of the platform, for a more consistent experience and cleaner data.

## Bug fixes

- **H-1B second worksite toggle now persists.** Unchecking "second physical work location" on an H-1B petition now correctly removes the secondary worksite instead of leaving stale data behind.

</Update>

<Update label="July 10, 2026" description="Week of July 6 – July 10">

## New features

**USCIS filing-fee Stripe invoicing.** Staff can now build itemized filing-fee invoices for a petition directly from the admin sidebar and send the client a single Stripe invoice with a hosted invoice page and pay link.

- Build a breakdown from the seeded USCIS filing-fee catalog via a dropdown, plus add editable custom line items.
- All amounts are staff-editable before sending, so you can reflect the current fee schedule or one-off adjustments per petition.
- The recipient signatory is resolved using the existing employer-signatory logic, and the Stripe customer's email stays in sync with the selected recipient.
- Sent (unpaid) invoices can be voided from the admin — the invoice is voided in Stripe and the local record moves to a `void` state.
- Send, finalize, and void calls are idempotent, so a double-click or retry can't create duplicate customers or invoices.

Filing-fee invoicing is gated on a Stripe API key. Until it's configured, the card shows a graceful "not configured" state and no invoicing actions run.

**Company Support Letter for every visa type.** The employer-signed Company Support Letter (previously labeled "H-1B Support Letter") is now available in the Form Signing company-signatory section for every visa type, including O-1A, EB-1A, and any future visa types — not just H-1B.

## Updates

- **Filing group in the admin sidebar.** The Filing Fee Invoice card lives in the sidebar's Filing group, and sidebar navigation now scrolls the target section into view below the sticky top nav.
- **Graceful release upgrades.** When a new version of LegalOS ships, the app no longer auto-reloads mid-session. Instead, an update banner appears so you can finish what you're doing before refreshing — a stale-page error will surface the banner instead of silently reloading and losing an in-progress form. Version checks now run on mount and when you refocus the tab, rather than polling every minute.
- **Additive auto-fill for visa history and passport countries.** Auto-fill for U.S. visa history and passport countries now merges into existing entries instead of overwriting them, so previously entered rows are preserved when new data is added.

## Coming soon

- Paid-status webhook and a client-facing invoice to-do so applicants can see and pay their filing-fee invoice from their portal.

</Update>
